## 这是什么

项目里每一条**实际生效的授权**都在这里有一行流水：成员、权限节点、来源、授予人、创建时间、过期、状态。来源分：

| 来源 | 意思 |
|---|---|
| 自确认 | 成员自己「一键激活」拿到的角色 / 部门默认权限 |
| 审批 | 申请后被批准的 |
| 直接授予 | 管理员在权限中心人事页给的 |
| 指派 | 因为被指派了任务 / 事件而带来的 |
| 系统 / 自动 / 迁移 | 系统生成、自动派发、历史数据迁入 |

![权限审计](/manual/admin/audit.png)

## 怎么操作

- 顶部筛选：成员、资源类型、来源、状态（有效 / 已撤销 / 已过期）。查「某人到底能不能改剧本」，就是成员选他、资源类型选剧本、状态选有效。
- 每行末尾「撤销」——立即收回这一条。被撤销的行保留，状态变「已撤销」。
- 分页浏览；顶部数字是流水总数和当前页内的有效 / 撤销数。

## 注意事项

- 撤销的是**这一条**授权。同一个权限他可能还从别的来源拿到（角色给了一次、申请又批了一次）。撤之前先把筛选设成**这个成员 + 这类资源 + 状态「有效」**，屏幕上剩下的就是他在这类资源上的全部有效授权，逐条撤干净，再通知他。撤销立即生效，不需要他做任何事。
- 角色和部门带来的自确认行，改角色模版或调部门归属会自动处理，不用逐条撤。

## 常见问题

**为什么一个人有几百条流水？**
每个权限键一行。一个职位的模版就有三四十个键，多个职位加部门就上百。这是正常的。
