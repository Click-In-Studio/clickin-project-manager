## 这是什么

**任务**是一件要某个部门或某个人去做的事。它有两个来源：

- **事件里提的技术需求**（「这场要一台雾机」）——自动成为任务，绑定在那个事件上。
- **独立任务**——不属于哪场排练的事（「更新技术合成预算」）。

「制作 → 任务」把两种汇总在一起。有些地方还叫它「技术需求」，是同一样东西。

![任务列表](/manual/production/tasks.png)

### 状态

| 状态 | 意思 |
|---|---|
| 待确认 | 事件给部门发的需求，等该部门 POC 确认接下 |
| 待处理 | 接下了，还没开始 |
| 进行中 | 在做 |
| 已阻塞 | 有前置任务没完成，被挡住了 |
| 完成 | 做完了 |

顶部四个数字：待处理（含待认领）、进行中、已阻塞、本周完成度。

## 怎么操作

### 筛选

- **我的任务 / 全部**：只看指派给我的，还是全项目。
- **关联事件**：某一场事件的、或者独立任务。
- **部门**、**状态**下拉。
- 「在日历中查看」跳到项目日历。

### 新建

「＋ 新建 Task」：

1. 任务名称、说明（背景、验收标准）。
2. **绑定对象**：不关联（独立任务）、某个事件、事件下的某条流程项、或者里程碑。不填时间时，任务继承绑定对象的起止。
3. 部门、负责人、开始 / 截止。
4. 「创建任务」。

没有创建独立任务权限的人（多数部门成员）可以走 **POC 路径**：把任务绑到你担任 POC 的部门，就能建。

### 处理

点任务行打开详情抽屉，可以改状态、指派、写说明；「打开完整详情页」看依赖和绑定。

## 注意事项

- 「待确认」是给部门 POC 的：事件发来的需求要 POC 点确认才算数。POC 会收到「技术需求待处理」通知。
- 任务的负责人只能由该部门的 POC 或有指派权限的人填。

## 常见问题

**任务和事件里的「技术提需」是同一个东西吗？**
是。在事件里提的需求就是绑定了这个事件的任务，两边改的是同一条。
