## 这是什么

**事件**是一次把人叫到一起的安排：围读、排练、演出、会议。它有时间、地点、参加的人，下面还挂着当天的流程、各部门的技术需求、每个人的到场时间（Call Time）、事后的报告。

四种类型：**排练 / 演出 / 会议 / 其他**。

「制作 → 事件」列表分「即将发生」和「已过去」两段，每张卡片上有日期、类型、标题、时间地点、状态，和几个入口：事件详情、执行流程、任务、「关注」。

![事件列表](/manual/production/events.png)

### 状态

| 状态 | 意思 |
|---|---|
| 草稿 | 建好了但只有能编辑的人看得到；参加的人还没收到通知 |
| 已发布 | 所有人可见，Call Time 通知已发出 |
| 已完成 | 结束了 |
| 已取消 | 取消了，保留记录 |

页面顶部画着事件的三步：**定义事件**（类型、时间、地点、人员）→ **确认任务**（负责人、截止、通知对象）→ **发布与追踪**（站内通知、确认、执行）。

> [!📱] 在手机和窄窗口中，这三步会紧凑地排在同一行，从左到右阅读即可。

## 怎么操作

### 新建

1. 「＋ 新建事件」。
2. 填标题、类型、日期、开始 / 结束时间、地点、备注。
3. **通知部门（创建待确认需求）**：勾选要通知的部门——每个勾选的部门会自动收到一条「待确认」的任务，由该部门的 POC 确认。这是最省事的「叫上灯光和音响」的方式。
4. 「创建」。新事件是**草稿**，进详情页补流程和 Call Time 再发布。

也可以在「项目日历」里点空白格快捷新建。

### 关注

卡片上点「关注」，即便你不在参加名单里，首页「我的工作」也会列出这个事件，它的报告发布时你会收到「报告发布通知」，首页「报告」块里也会有未读。制作人、导演通常关注所有排练。

## 注意事项

- 通知只在**发布那一刻**发一次。之后改时间、地点、流程，或者取消，系统都不会再通知——所以先在草稿里排好再发；发布后有大改动，在群里说一声，或者撤回重新发布。
- 一个事件只能有一个日期。连排三天就是三个事件，用「项目日历」看整体。

## 常见问题

**「执行流程 →」和「事件详情 →」有什么区别？**
执行流程直接跳到「计划与日程 → 执行日程」里这一天的现场表；事件详情是事件本身的全部信息。
