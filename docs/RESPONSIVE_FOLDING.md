# 响应式折叠设计

本文记录 Production 页面与打印预览的响应式折叠实现。开发通用要求见 [DEV_GUIDE.md](./DEV_GUIDE.md)。

折叠由几套相互独立的状态机组成。固定视口断点只处理 shell；实际剩余空间只处理页面工具栏；打印预览再维护自己的工具栏阶段。一个系统变化不得重置、代替或跳过另一个系统的阶段。

## 1. 固定视口宽度：Shell 与剧本侧栏

`AppShell` 的 Header Stage 只由 `window.innerWidth` 决定：

| Header Stage | 条件 | 行为 |
|--------------|------|------|
| 0 | `>= 1280px` | 完整显示 |
| 1 | `1024px - 1279px` | 隐藏 Backstage 文本 |
| 2 | `< 1024px` | 继续隐藏通知与个人入口 |

剧本页的 production 侧栏是另一套固定宽度逻辑：

- `>= 1496px`：默认显示 `240px` 完整侧栏，并允许用户手动折叠为 `72px`。
- `1024px - 1495px`：自动折叠为 `72px`；临时展开时使用覆盖层，不挤压剧本工作区。
- `< 1024px`：桌面侧栏隐藏，由底部导航和抽屉承载相同入口。

侧栏展开/折叠只改变可用空间，不能直接指定页面工具栏阶段；工具栏必须根据变化后的实际空间自行测量。

## 2. 剩余空间：共享 Production Toolbar Stage

`AppShell` 测量顶部栏的固有内容宽度与可用宽度，并通过 `ProductionToolbarStageContext` 向页面发布以下命名阶段：

| Stage | 常量 | 共享含义 |
|-------|------|----------|
| 0 | `full` | 完整显示 |
| 1 | `searchCollapsed` | 搜索框折叠为搜索图标 |
| 2 | `secondaryStored` | 收纳页面二级控件 |
| 3 | `primaryShort` | 一级控件改用短标签或紧凑形态 |
| 4 | `primaryStored` | 一级控件收入共享三点菜单 |
| 5 | `lowPriorityStored` | 收纳最后的低优先级控件 |

只有当前阶段仍溢出时才能前进一阶段；空间恢复时必须逐级反向展开，并比进入前一阶段时记录的宽度多出 `16px` 才能展开，避免临界宽度抖动。搜索展开期间暂停折叠测量。

项目名与页面名组成的页面摘要在所有阶段都必须保留。控件按以下方式响应共享阶段：

| Stage | 剧本页 | Cue 页 | Cue 设置页 | 构作页 / 角色页 |
|-------|--------|--------|------------|-----------------|
| 0 | 完整工具栏 | 分享、行/页/段落跳转、导出、设置完整显示 | 「新建」显示在顶部工具栏 | 完整工具栏 |
| 1 | 无额外变化 | 无额外变化 | 无额外变化 | 无额外变化 |
| 2 | 无额外变化 | 跳转项合并为「跳转」；分享与 Cue 表入口合并为「设置」 | 无额外变化 | 构作表格视图的视图与列设置收入共享三点菜单 |
| 3 | 章节、角色、编辑、显示及排练模式使用短标签；在线头像最多显示 2 个 | 可见 Cue 标签收入当前 Cue 菜单；当前 Cue 触发器限制为 `118px`；「插入 Cue」移至底部浮动按钮 | 「新建」移至筛选标签行最右侧 | 列表/表格切换只显示图标 |
| 4 | 章节、角色、编辑、显示、导出收入共享三点菜单 | 跳转、导出、设置收入共享三点菜单；设置内保留「分享当前 Cue 表」与「Cue 表设置」 | 「新建」仍留在筛选标签行，不收入三点菜单 | 列表/表格切换收入共享三点菜单 |
| 5 | 在线成员收入共享三点菜单 | 无额外变化 | 无额外变化 | 无额外变化 |

页面没有某一级控件时可以表现为无变化，但不能改变后续阶段的编号或含义。一级控件是页面核心入口或视图切换；二级控件是依附于当前视图的设置。

## 3. 测量与菜单归属

- 可伸缩或横向滚动的完整内容容器必须标记 `data-production-toolbar-flex-content`。`AppShell` 测量该容器的固有宽度和外边距，不能使用已经被裁切后的外层宽度。
- 页面通过 `ProductionTopMenu` 的 overflow slot 把已收纳控件交给共享三点菜单。只要已有页面控件被收纳，折叠后的搜索入口也收入该菜单并固定为第一项；否则搜索保持独立图标。
- 从共享菜单展开的子菜单使用 anchored portal，并标记为 overflow menu child，避免点击子菜单或移动鼠标时误关父菜单。
- 剧本工具栏的菜单开关状态由 `ScriptToolbarMenuController` 持有，不得放回完整 `ScriptEditor`，否则每次开关菜单都会让整个虚拟剧本窗口重新渲染。
- `ScriptEditor` 仅在不位于共享 production toolbar slot 时启用本地 `full -> short -> compact` 空间折叠作为独立使用场景的后备方案；正常 production 剧本页以共享 Toolbar Stage 为准。本地方案同样使用 `16px` 展开缓冲。

带内部滚动区的 production 页面必须使用 `PRODUCTION_PAGE_SCROLL_ROOT_CLASS`（`h-full min-h-0 overflow-hidden`）占满 `AppShell` 分配的 workspace，不得再次用 `100vh` 计算页面高度。底部导航出现时由 `AppShell` 压缩 workspace，页面只保留自身的一条滚动区。

## 4. 打印预览的独立折叠

打印预览不使用 Production Toolbar Stage。它测量自己的单行工具栏，并维护独立的 `PrintToolbarStage`：

| Print Stage | 行为 |
|-------------|------|
| 0 | 页眉位置、紧凑排版、完整「缩放 xx%」、「打印 / 导出 PDF」、关闭全部展开 |
| 1 | 「紧凑排版」缩为「紧凑」，缩放入口只显示百分比，「打印 / 导出 PDF」缩为「导出」 |
| 2 | 紧凑排版、页眉位置和缩放合并为「页面设置」；导出与关闭保持直接可用 |
| 3 | 除导出与关闭外的全部控件收入工具栏最右侧的三点菜单 |

Stage 2/3 的页面设置内容必须在同一层完全展开：紧凑排版、全部页眉位置选项、可编辑百分比、加减按钮、缩放条、适合宽度和适合整页，不得再生成页面设置或缩放子菜单。预览默认使用适合宽度；用户手动输入、拖动、点击加减、使用 `Ctrl/Cmd + +/-` 或在预览区按住 `Ctrl/Cmd` 滚轮后进入自定义缩放。`Ctrl/Cmd + 0` 恢复适合宽度。

打印工具栏也只在溢出时逐级折叠，反向展开保留 `16px` 缓冲。所有阶段保持单行，导出与关闭永不收入三点菜单。
