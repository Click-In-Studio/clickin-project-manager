## 执行与补偿

脚本：`scripts/admin/run-asset-orphan-cleanup.sh`，快照与补偿 SQL 在同目录。以 postgres 用户执行，先 dev 后 prod；每个环境独立核对 release、数量与摘要。

1. `prepare`：完整 pg_dump 及可读取目录清单；完整候选行 JSON 快照；非目标 grant、三类区间、策略、节点、资产的合并摘要；脚本 SHA-256 清单。目录 700、文件 600，仅 postgres 可读。
2. `rehearse`：同一事务执行清洗和定向补偿，逐行比较原始快照后整体回滚，不留下迁移记账。
3. `apply`：dbmate 只加载本次 migration。3 秒锁超时、15 秒语句超时；持锁后核对完整目标行摘要，不一致则事务回滚。迁移由 dbmate 写入 schema_migrations。
4. 核对仅目标行的两个字段改变、剩余候选为 0、非目标摘要不变及迁移记账。任何失败停止后续环境。
5. 必须补偿时执行 `restore`：仅在目标行仍精确等于本次清洗后的状态、实体仍不存在时还原两个字段；后续修改导致整笔拒绝。保留 schema_migrations 历史，不执行不可逆 down，不直接恢复整库覆盖后续业务写入。
