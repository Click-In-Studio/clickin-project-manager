# 【后台】执行日程列编辑与地点配置交互不一致

GitHub Issue：[#283](https://github.com/Click-In-Studio/clickin-project-manager/issues/283)

## 来源

2026-08-19 在本地 Demo 项目 `demo-misty-harbor` 的浏览器回归中触发。页面：

`/production/demo-misty-harbor/planning`

## 问题表现

1. 执行日程编辑模式下，人员组列缝的插入按钮命中范围偏小，`+` 字形未居中，浏览器原生提示气泡与产品视觉不一致。
2. “未归入地点”只承担展示作用，无法直接把当前人员组区段创建为一个地点。
3. 地点编辑栏采用实时保存，但没有明确的“确认”动作，用户难以判断修改是否完成。
4. 用户离开“计划与日程”后再次进入时，总是回到“项目日历”，无法恢复上次使用的“任务甘特”或“执行日程”。

## 预期结果

- 列缝具备稳定、易命中的插入热区，按钮和反馈符合现有视觉规范。
- 点击“未归入地点”即可创建地点，并自动带入该连续区段的人员组。
- 地点编辑栏明确提示自动保存，同时提供“确认”按钮完成并关闭编辑。
- 按项目记忆最后使用的计划视图，刷新或重新进入页面后恢复。

## 本分支处理

- 重构列头菜单与插入按钮样式，移除原生提示气泡并统一悬停、聚焦和按压反馈。
- 为地点区段补充人员组 ID 集合，支持从“未归入地点”一键创建并归组。
- 地点编辑栏新增固定底部操作区、“更改已自动保存”提示和“确认”按钮。
- 使用 `planning-last-view:<productionId>` 保存项目级最后视图。

## 验收记录

- `npx tsc --noEmit`：通过。
- `npx eslint components/PlanningClient.tsx`：0 error。
- 浏览器回归：快捷建点、确认关闭、删除测试地点和刷新恢复“执行日程”均通过。
