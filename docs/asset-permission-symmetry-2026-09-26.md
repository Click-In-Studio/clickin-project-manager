## 验证矩阵

- 单点与列表同源：公开、部门分享、直接授权、每种挂载与嵌图、无壳、撤销、过期。
- 树与内容分离：隐藏父链、局部枚举、软链接、创建者授权撤回；直接授权不绕过隐藏父链。
- 写面：只持重命名、删除、追加文件、授权管理、单向旧发布键分别验证。
- 挂载创建保留双方门；撤挂允许任一方终止，通用与旧资产路由一致。
- 下载与外链：预览权不代替下载操作权，外链策略与外链创建权分别检查。
- 列表、详情、树内预览、引用搜索、AI 工具都消费同一读取判定。
- 迁移：已激活行、区间、默认模板、创建者发行、策略、过期撤销信息及 N-1 兼容。

## 后续线上整理的执行边界

当前 PR 只修复菜单与下载门，不修改权限行、区间、策略或节点的公开设置。#427 保持开放。

线上整理分两阶段，dev 与 prod 分别出结果，不能把 dev 的统计当作 prod 的事实：

1. **只读盘点与模拟**：核对部署版本、`schema_migrations`、有效及失效授权、三类区间、项目模板、策略、资产与节点/父链、挂载和部门分享。汇总输出避免包含文件正文、外链令牌、用户联系方式和环境密钥。按项目及规则列出待转换记录、原有受众、新增/减少的受众、只持单向旧发布权的例外和失效授权；不自动删除孤儿行。
2. **经审阅后分环境实施**：先形成版本化 migration、迁移测试及执行前快照，再按用户明确授权先 dev 后 prod 执行。新旧读取规则在切换前做差异校验。意外新增私有读取权、意外丢失既有读取权、仅列出资产受众不确定、部署版本不匹配或快照后源数据已变化时停止，不强行继续。

具体转换约束：

- 旧的资产域能力票不得重解释为全库私有读取权；迁移同时覆盖已激活行、角色/部门/个人区间与默认模板，不能让下一次自确认重新发回旧语义的通配票。
- `publication@view` 的既有显式全库读取语义应保留；撤销/过期、来源、审批与授予者信息不丢失，不把临时授权变成永久授权。
- 单向的 `publication@create` / `publication@delete` 不直接升级为完整 `grants@edit`；列为兼容例外，明确收敛规则后再迁移。
- 仅列出而未公开的资产不批量设成公开；按它们的实际受众处理。挂载、部门分享等动态可见性不拍平成个人 grant，撤挂或退出部门后仍应收缩。
- 下载和对外分享分别核对，不因站内分享统一而增加原件下载或对外链接发行权。

回滚准备：迁移前记录代码版本、迁移版本和被影响行的完整快照；dev 先演练失败回滚及恢复后的权限矩阵。数据回填按仓库规定声明不可逆 down，恢复使用审阅过的补偿方案或维护窗口内备份恢复，不伪造一条能还原用户后续改动的 down。未经验证，不承诺只回退代码即可恢复旧授权边界。

上述是实施与验收约束，不是已经可在线运行的转换 SQL。最终键映射、逐项目差异清单和补偿脚本须在写入授权前完成并提交审阅。
