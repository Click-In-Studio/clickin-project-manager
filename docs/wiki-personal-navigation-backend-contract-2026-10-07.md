# 云文档最近访问后端契约

> 来源：#895 / #896 的个人导航设计、前端 PR #916。
> 2026-10-10：按 owner 定案收敛为最近访问；置顶不在本轮实现范围。

## 1. 功能范围

- 保存当前账号在当前项目最近实际打开且有权阅读的文档。
- 同一账号跨设备、跨会话读取一份历史；不同用户、项目完全隔离。
- 只保存 canonical wiki id 与服务端访问时间，不保存正文、标题副本、设备、viewport、光标或阅读进度。
- 最近访问是导航历史，不包含设备间实时同步、阅读位置恢复或跟随。
- 不实现置顶、访问统计、跨项目聚合、离线队列或历史补报。

## 2. 一次性记录语义

正文成功呈现且页面可见后，客户端显式提交一次访问请求。
目录展开、hover、搜索结果、预取、打印、分享、权限申请、后台读取和正文滚动不记录访问。

请求失败或超时即结束，不自动或手动重发这次访问、不离线积压、不恢复后补报。
允许漏记，记录过程不能阻断阅读。超时不能断言一定未落库；客户端如提示，应表达“未能确认”。
再次实际打开文档属于新的访问；窗口焦点、列表刷新、恢复网络不自动制造新访问。

同一文档只存一行，重复访问更新访问时间。这是状态去重，不是严格的事件幂等：
重复提交仍可能推进时间，因此不能以“upsert”为理由重试。

访问时间以数据库收到写入语句的时间为准（statement_timestamp），冲突更新用 GREATEST 保证不倒退。
列表按时间倒序、wiki id 倒序稳定排序。弱网下不承诺跨设备真实点击顺序；也不保证一个并发访问期间的目标永远排在第一。

## 3. 数据模型

wiki_recent_visit：

- id：TEXT PRIMARY KEY，应用侧带随机尾的 short id。
- user_id：UUID，app_user 外键，删除级联。
- production_id：TEXT。
- wiki_id：UUID，真实文档 id。
- last_viewed_at：TIMESTAMPTZ NOT NULL。
- UNIQUE (user_id, production_id, wiki_id)。
- FOREIGN KEY (wiki_id, production_id) REFERENCES wiki(id, production_id) ON DELETE CASCADE。

wiki 同批增加 (id, production_id) 唯一约束。项目删除经 wiki 级联删除历史。
排序索引为 (user_id, production_id, last_viewed_at DESC, wiki_id DESC)，另设 (wiki_id, production_id) 索引支持文档删除。

保留全部每文档当前状态，不做写时裁剪，不回填虚构访问。
标题查询时从 wiki 获取当前值，允许 null。

## 4. API

### GET /api/production/:productionId/wiki-personal

只返回 session 用户自己的历史；不提供其他用户参数。
响应保持 #916 已消费的结构：

```json
{
  "pinned": [],
  "recent": [
    {
      "wikiId": "00000000-0000-0000-0000-000000000000",
      "title": "第一轮创作汇报",
      "lastViewedAt": "2026-10-10T02:10:00.000Z"
    }
  ]
}
```

pinned 固定空数组，不代表实现置顶。recent 固定最多 20 篇；前端显示前 5 篇。
按索引分批读取候选，复用 listVisibleWikiIds 的候选集判定；权限过滤后再截断，直到得到 20 篇或历史耗尽。
不能先取 20 篇再过滤，也不能枚举整个项目或逐篇 N+1。
分页游标保留数据库时间精度，不使用 JSON 毫秒时间作游标。
响应 Cache-Control: private, no-store，禁止缓存历史及权限结果。

### POST /api/production/:productionId/wiki/:wikiId/visit

请求体必须为空，成功返回 204，无响应体。
user 与时间只能来自 session / 数据库；客户端不能提交标题、用户、时间或整份历史覆盖服务端。
接口只接收真实 wiki UUID，node/link 入口沿用页面已有解析，传入 canonical wiki id。
直接入口和软链接访问归一到同一条记录；删除软链接不删除目标文档的历史。

鉴权顺序：session → 项目上下文 → 文档存在且同项目 → canViewWiki → 请求体校验 → 写入。
owner 旁路前必须确认文档存在与项目归属。
归档项目允许保存个人访问历史，因为没有修改项目内容。

### 错误

- 无 session：401。
- 非成员、停用/退出成员且非 owner，或没有项目上下文：403。
- 不存在、非 UUID、node/link id、跨项目目标：404。
- 项目内不可读：403；不披露 id、标题、时间、占位或申请锚。
- 已授权但请求体非空：400。
- 数据库等服务端失败：请求失败，不隐式重试。

## 5. 权限与删除

- 每次 GET / POST 按当前内容阅读门判定，不能把目录枚举权当阅读权。
- 可读但不可枚举的文档允许出现在个人历史。
- 历史不授予阅读、下载、管理或任何 grant，不查询其他人的历史。
- 撤权后 GET 隐藏全部条目信息，底层记录保留；恢复权限后历史恢复。
- 文档、用户、项目实际删除时级联清理。
- 点击条目仍由正文页面重新通过权限门。

## 6. 前端协作

#916 保持一次性 POST，不添加重试、补报或 viewport 状态。
后台标签页应等正文实际可见后记录，过期响应不能改变当前页面。
列表 GET 可以手动重试；只重读列表，不重发访问记录。
记录请求结束后读取列表，返回前台时也可读取；不承诺另一设备实时刷新。
首次失败不能伪装为空历史；同账号同项目后台刷新失败可保留上次结果，明确未更新。
收到明确 401/403、退出账号或切换项目时不得继续显示原账号/项目结果。

## 7. 交付与验收

后端独立 PR，关联 #923；前端仍由 #916 交付。没有前端入口时，不宣称用户侧功能已经上线。

- migration + schema.sql + 生成指纹三方一致，从 origin/main 旧 migrations 验证升级。
- 401、非成员/停用成员 403、单枚无关键与单文档授权、owner 存在性、跨项目、非空请求体。
- 用户/项目隔离、同账号多会话共享、当前标题/空值、只读 GET 不产生访问。
- 公开策略、部门分享、个人行、宿主/报告挂载通道的候选集与现有内容门同源。
- 撤权隐藏/恢复、过滤跨批次后仍返回 20 篇、微秒游标、同时间稳定排序、不裁剪历史。
- 并发唯一、旧请求等锁完成后不倒退、复合 FK 与三个删除级联、索引路径。
- 与 #916 联合进行真实接口和浏览器验收，覆盖弱网、失败只请求一次、两设备共享列表且 viewport 独立。
